# Profile asset generators

All SVGs under `assets/` (except `whoami.svg`, which is hand-written) are
generated by the scripts in this directory. The README loads them via
`<picture>` + `prefers-color-scheme`, so every generator emits a `-dark`
and a `-light` variant.

## Radar charts (`radar.py` — stdlib only, no deps)

Skill radar, from the self-rated data in `assets/skills.json`:

```bash
python3 scripts/radar.py --data assets/skills.json -o assets/radar
```

Language radar, live from the GitHub API:

```bash
python3 scripts/radar.py --github MrDylanDev -o assets/radar-langs
```

The GitHub scan makes one `/languages` call per non-fork, non-archived
repo. Unauthenticated quota is 60 requests/hour; set `GITHUB_TOKEN` or
`GH_TOKEN` if you have more repos than that. The script aborts loudly on
rate-limit exhaustion rather than rendering a partial radar.

Useful flags: `--curve 0.5` (default, sqrt compression of lopsided byte
ratios), `--values` (print numbers per axis), `--no-animate`.

## Profile banners (`banner/` — NOT regenerable from a clean clone)

```bash
pip install -r scripts/banner/requirements.txt
python3 scripts/banner/generate.py   # writes assets/banner-{dark,light}.v9.svg
```

Two inputs live **outside** this repository and are required:

- `assets/source/portrait.png` — the source portrait photo (never committed).
- `scripts/banner/logos/linux.*` — the Linux icon. The shipped banner was
  built with the sequence `linux → kubernetes`, but only `kube.webp` is
  committed, so regenerating today produces a single-logo animation that
  does not match the published asset.

Drop both files in place, then run the generator. Bump the `.vN` suffix in
`main()` and in the README `<picture>` tags when the design changes — the
version in the filename busts GitHub's image cache.

## Regenerating after edits

Radar edits are fully reproducible; banner edits need the two external
files above. When in doubt, only ship changes you can regenerate.
